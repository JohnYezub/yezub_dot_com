Каждое измерение должно помогать принять решение: где теряются пользователи, кто возвращается, за что платят и какие каналы окупаются.


Для анализа поведения выберите одну систему: [Firebase](https://firebase.google.com/docs/analytics/get-started), [Amplitude](https://amplitude.com/docs), [Mixpanel](https://docs.mixpanel.com/docs/what-is-mixpanel) или [PostHog](https://posthog.com/docs). Сравните нужные отчёты, поддержку платформ, экспорт и стоимость при вашем объёме.

## Минимальный набор для начала

Для старта нужны продуктовая аналитика, учёт сбоев, отчёты магазинов и надёжный учёт платежей. MMP полезнее при нескольких рекламных каналах и сложных переходах; для отдельных режимов кампаний площадка может требовать партнёрскую интеграцию.

SDK — библиотека для подключения сервиса к приложению. Каждый лишний SDK добавляет поддержку и работу с данными; не устанавливайте несколько одинаковых систем «на будущее».

## Как внедрять

Сначала составьте план измерения. Затем заведите проект сервиса, зарегистрируйте платформы приложения, подключите SDK, задайте правила согласия и отправки данных, добавьте события и проверьте их. Разделите тестовые и реальные данные, назначьте владельца событий, создайте первые отчёты.

Для Firebase проверка событий доступна в DebugView. После проверки на тестовом устройстве убедитесь, что данные приходят и из выпущенной версии. [Регистрация событий](https://firebase.google.com/docs/analytics/events), [DebugView](https://firebase.google.com/docs/analytics/debugview).
