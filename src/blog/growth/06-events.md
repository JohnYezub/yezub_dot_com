Событие (event) фиксирует действие; параметры уточняют контекст. Например, `forecast_viewed` — прогноз успешно показан, `entry_point` — откуда пришёл человек. Свойства пользователя описывают язык или тип доступа.

Фиксируйте точное условие: открытие экрана, загрузка и показ данных — разные события. Ошибки загрузки измеряйте отдельно.

## Начальный набор событий

Ниже — пример внутренней схемы. Это не готовый список стандартных событий каждого сервиса. При интеграции сопоставьте его с рекомендованными и автоматически собираемыми событиями поставщика, чтобы не создавать дубли.

| Событие | Когда отправлять | Что помогает узнать |
| --- | --- | --- |
| `first_open` | Первый запуск в значении выбранного SDK | Сколько установок дошло до использования |
| `onboarding_started` | Начался вводный сценарий | Сколько людей увидело обучение |
| `onboarding_completed` | Выполнен последний обязательный шаг | Где заканчивается вводный сценарий |
| `forecast_viewed` | Актуальные данные успешно показаны | Получена ли первая часть пользы |
| `location_saved` | Место действительно сохранено | Подготовлен ли повторный сценарий |
| `paywall_viewed` | Экран предложения доступен пользователю | Сколько людей видит монетизацию |
| `purchase_started` | Начат процесс покупки | Есть ли намерение приобрести доступ |
| `trial_started` | Подтверждён пробный доступ | Сколько людей начали пробу |
| `purchase_verified` | Подтверждена платная транзакция | Сколько покупок состоялось |
| `subscription_renewed` | Подтверждено очередное списание | Продлеваются ли подписки |
| `subscription_expired` | Доступ закончился | Сколько подписчиков потеряно |
| `refund_confirmed` | Подтверждён возврат | Насколько доход устойчив |
| `share_completed` | Известный приложению факт отправки | Используют ли функцию обмена |

Открытие системного меню «Поделиться» ещё не означает отправку. Если платформа сообщает только открытие меню, назовите событие `share_sheet_opened`. Аналогично нажатие кнопки оплаты не считается покупкой, а отключение автопродления не означает немедленную потерю доступа.

## Паспорт события

В паспорте события укажите определение, момент отправки, источник, владельца и параметры. Общие параметры: версия, платформа, язык, вариант эксперимента, время. Для платежа добавьте валюту, сумму, товар, ID транзакции и тестовую среду.

Не включайте в аналитику пароли, платёжные реквизиты, email, свободный текст и точные координаты без обоснованной необходимости. Если достаточно региона, передавайте регион. Серверная отправка не отменяет требований к данным.

## Защитите смысл данных

Определите, как анонимный пользователь связывается с аккаунтом после входа, что происходит после выхода и как учитываются разные устройства. Не используйте email как открытый идентификатор аналитики. Не считайте переустановку гарантированно новым человеком.

Для событий платежей используйте проверку транзакции и защиту от повторной обработки по её идентификатору. Повторно доставленное уведомление не должно увеличивать выручку второй раз. Отдельно храните время действия и время получения: задержка доставки может менять дневные отчёты.
